# 29인의 선택 — 연말 모임 웹게임

## 게임 콘셉트

- 사회자가 현장에서 한 순장을 발표합니다. 참가자는 **그 순장이 내릴 법한 선택**을 총 15번 고릅니다.
- 참가자의 15개 선택과 사전 수집된 29명 전원의 답변을 비교합니다.
- 가장 많이 일치한 순장을 공개합니다. 사회자가 발표했던 순장과 다른 사람이 나올 수 있다는 점이 핵심 반전입니다.
- 사회자가 발표한 순장의 실제 답변과 일치 개수, 29명 중 순위, 서로 달랐던 답변을 확인할 수 있습니다.
- 점수가 같으면 **공동 순위**입니다. '성격 유사도' 같은 과학적 의미의 점수가 아니라 **선택 일치 개수**를 사용합니다.

## 파일

- `index.html`: 참가자 화면 (주인공 선택 메뉴 **없음**)
- `host.html`: 사회자 전용 도구 (주인공 지정, 라운드 URL 및 QR 만들기, 설문 CSV 입력)
- `questions.js`: 15개 상황형 질문 (수정하면 `questions_for_google_form.txt`와 응답 양식도 같이 수정해야 합니다)
- `data.js`: 현재는 **29명의 가상 샘플**입니다. 실제 데이터로 교체하세요.
- `survey_template.csv`: 실제 응답을 채우는 표준 템플릿
- `questions_for_google_form.txt`: 구글폼 문항 복사용
- `styles.css`, `game.js`, `host.js`: 화면 디자인과 게임 동작

## 1. 구글폼 만들기

1. 구글폼을 만들고 맨 앞에 **순장 이름**을 필수 단답형으로 만듭니다.
2. `questions_for_google_form.txt`의 15개 문항을 **각각 객관식 단일 선택**으로 등록합니다.
3. 선택지는 가급적 `A. ...`, `B. ...`, `C. ...`, `D. ...` 형식을 유지합니다.
4. 29명에게 응답을 받고 Google Sheets 연결 후 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)** 또는 CSV 파일로 내보냅니다.
5. 중복 응답과 미완료 행을 정리하여 **29명 × 15문항**이 되도록 합니다.
6. 개인적 고백이나 민감한 응답을 웹에 노출하지 않도록, **각자의 선택 결과가 게임에 공개되는 데 동의**를 구하세요.

**자동 생성 대안:** Google Apps Script에서 `google_form_builder.gs`의 코드를 붙여 넣고 `createYearEndForm()`을 실행하면 이름 문항, 15개 선택 질문, 응답 공개 동의 문항이 포함된 구글폼을 자동 생성할 수 있습니다. 실행 로그에 편집 링크와 응답 링크가 표시됩니다.

## 2. 데이터 파일 만들기

1. `host.html`을 엽니다.
2. **답변 등록** 항목에서 내려받은 CSV를 업로드합니다.
3. 29명의 이름과 15개 문항을 인식하면 `data.js` 다운로드 버튼이 활성화됩니다.
4. 다운로드한 `data.js`로 이 폴더 안의 기존 **샘플 `data.js`**를 교체합니다.
5. CSV 인식이 안 되면 `survey_template.csv`에 **id / name / q01…q15** 열을 그대로 채워 다시 업로드하세요. `id`는 `p01`부터 `p29`까지; 답변은 `A`, `B`, `C`, `D` 중 하나입니다.
6. 동일한 답 패턴을 제출한 순장은 자동으로 경고합니다. 이런 경우에는 두 순장의 결과가 언제나 공동 순위가 될 수 있어, 서로 구별하는 추가 질문을 마련하면 좋습니다.

> **주의**: 업로드는 브라우저 안에서 처리하며 별도의 서버에 전송하지 않습니다. 하지만 실사용 `data.js`를 공개 웹사이트에 업로드하면 그 내용은 공개적으로 접근 가능합니다. 이름과 객관식 선택만 넣으세요.

## 3. 사이트 배포 (GitHub Pages 예시)

1. 새 GitHub 저장소를 만든 후 `build.py`를 제외한 웹 파일을 저장소 루트에 업로드합니다.
2. 저장소의 **Settings → Pages**에서 배포 소스를 브랜치(`main`, `/root`)로 설정합니다.
3. 배포된 주소가 `https://사용자명.github.io/저장소이름/`라면 게임은 그 아래 `index.html`에서 실행됩니다.
4. 사회자 도구는 같은 주소의 `host.html`로 접근합니다.
5. 사회자 도구에서 사이트 배포 주소를 입력하고 오늘의 순장을 선택해 **QR코드/URL**을 만듭니다.
6. 이때 참가자용 URL은 `.../index.html?t=p07`처럼 생성됩니다. `p07`은 파일상의 순장 ID입니다.

> 모든 사람이 **하나의 고정 QR**에 접속하고 사회자의 선택이 즉시 바뀌도록 하려면 실시간 세션 저장소(서버)가 필요합니다. 지금 제공하는 무료 정적 버전은 **라운드마다 사회자가 다른 QR을 보여주는 방식**입니다.

## 4. 모임 당일 진행 (15~20분)

1. 사회자: “이번에는 ○○순장님의 마음을 읽어보겠습니다!”
2. 해당 순장에 대한 QR코드를 화면에 띄워 참가자들이 접속합니다.
3. 참석자들은 모든 15문항에 **그 순장이라면 어떻게 답했을지** 선택합니다.
4. 결과 화면에서 다른 순장이 1위로 등장할 수 있습니다. 사회자가 대표 몇 명에게 결과를 물어보면 재미있습니다.
5. 선택이 크게 달랐던 문항은 당사자에게 “실제로 왜 그 선택을 했나요?” 하고 물어볼 수 있습니다.
6. 29명 모두 데이터에는 들어 있으므로 **누구든 결과로 등장할 수 있으며**, 메인 행사에서 모든 순장을 하나씩 플레이할 필요는 없습니다.

## 테스트

- 기본 `index.html`을 열면 **샘플 순장 01** 라운드로 진행됩니다. 실제 순장 응답이 아니라 테스트용 데이터입니다.
- `host.html`에서 **샘플 순장 02**를 골라 미리보기 링크를 열면 해당 프로필로 진행됩니다.
- 데이터 교체 후에 웹사이트를 다시 배포해야 새 응답이 반영됩니다.

## 배포 전 체크

- [ ] 모든 실제 응답과 이름을 입력했다.
- [ ] 참가자에게 선택 결과의 공개 범위를 설명했다.
- [ ] `data.js` 샘플 배너가 사라졌다.
- [ ] 휴대전화에서 15개 문항과 결과 화면을 테스트했다.
- [ ] 동점과 잘못된 URL을 테스트했다.
- [ ] 실제 행사에서 쓰는 Wi-Fi/셀룰러로 접속을 시험했다.
